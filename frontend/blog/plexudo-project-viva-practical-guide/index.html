1. Understand the project

Main topic: Social Media Trend Analysis System.
Implemented scope: YouTube-Based Social Media Trend Analysis System.
Project name: Plexudo.

The main tool collects public YouTube video data, processes it into useful metrics, and displays the results through charts and tables. It helps users compare a retrieved sample of videos without manually opening and calculating every result.

The central distinction: popularity describes accumulated attention; measured growth requires comparable observations over time. One snapshot cannot prove that views are accelerating.

2. Your one-minute introduction

Assalam-o-Alaikum. Our project is Plexudo, a YouTube-Based Social Media Trend Analysis System. It retrieves public video data through YouTube Data API v3 and presents views, engagement, category distribution, and trend indicators in an interactive dashboard. Users can search a topic, apply filters, examine results, and export reports. Historical comparisons become available when sufficient comparable observations have been saved. The objective is to make public YouTube data easier to interpret while clearly distinguishing observed metrics from estimates.

Practice this in your own words. Follow it with a concrete example: a user searches for Minecraft and compares the views and engagement of the returned videos.

4. Metrics you must be able to explain

Engagement rate

((likes + comments) / views) × 100

Example: 400 likes and 100 comments on 10,000 views produce a 5% engagement rate. A zero denominator must be handled safely. An average of video engagement rates and an engagement rate calculated from combined totals are different aggregations; identify the value you are discussing.

Observed growth

((current views − previous views) / previous views) × 100

Example: a comparable total increases from 10,000 to 12,000 views: growth is 20%. State the observation interval. Growth over seven days is not automatically a daily growth rate.

Category totals and sample scope

Category totals summarize the retrieved videos. The highest-view category has the greatest accumulated views within that sample; this alone does not make it the fastest-growing category across YouTube.

Momentum and virality indicators

These are application-defined heuristic indicators, not official YouTube scores, measured growth percentages, or probabilities of going viral. A score of 61/100 does not mean a 61% chance of success. Explain the applicable implementation instead of inventing a universal formula.

Two different chart meanings

The upper view chart groups current lifetime views by upload age. The historical trajectory uses saved observations. Do not describe upload-age buckets as daily views gained. A baseline trajectory contains only the actual recorded point.

5. Historical tracking and projections

A baseline is the first saved observation. Comparisons require another suitable observation of the same selection. The current observation identity includes the topic, platform, region, category, timeframe and exact returned video IDs. If the video set changes, an earlier snapshot may no longer be comparable.

  • Observations are collected when searches run; a background collection schedule is not implemented.
  • Repeated immediate refreshes do not create meaningful daily history; comparable observations are spaced by at least 24 hours.
  • Waiting a month alone does not populate the 30-day window. Comparable saved data must actually exist.
  • “Data collection in progress” means evidence is insufficient. It does not mean zero growth.
  • The conservative projection requires at least three observations spanning 48 hours and an available velocity value.

The projection applies a bounded rate with dampening. It is illustrative, not a trained forecasting model or a guaranteed outcome. Its displayed bounds should not be presented as statistically validated confidence intervals.

Our system avoids presenting missing historical evidence as measured growth. Scheduled collection and more persistent video tracking are future improvements.

6. Sentiment and AI: describe the actual implementation

The sentiment service cleans sampled comments and uses TextBlob polarity. Values above 0.1 are labelled positive, values below −0.1 negative, and values between those thresholds neutral. Missing usable comments should be described as unavailable.

This is a sample-based estimate. Sarcasm, context and multilingual comments can reduce reliability; the current cleaning approach is oriented toward English text. It does not measure the opinion of the entire audience.

The main Trend Analyzer currently supplies editable topic-based title templates. Do not describe those templates as freshly generated by a large language model. Other platform AI services are separate integrations. Using an external model or TextBlob is not the same as training your own model.

7. Common viva questions and model answers

1. What problem does your project solve?

It reduces the manual effort needed to collect and compare public YouTube video metrics by organizing them in a searchable dashboard.

2. Why does the title say social media if you only support YouTube?

Social media analysis is the broader domain. YouTube is the implemented scope of this project; additional platforms are future work.

3. Why use an API instead of scraping?

The implementation uses the official API to obtain structured data and process defined response fields. It still depends on permissions, service availability and quota.

4. What is your contribution beyond calling an API?

The contribution combines input validation, data integration, calculated metrics, comparable observations, visualization, error handling and report generation into one usable workflow.

5. What is JSON?

JSON is a structured text format used to exchange objects and arrays between the backend and frontend.

6. What is the difference between frontend and backend?

The frontend handles interaction and presentation in the browser. The backend processes requests, communicates with external services and handles persistence.

7. What is an ORM?

An object-relational mapper lets application code work with database tables through model objects. This project uses SQLAlchemy through Flask-SQLAlchemy.

8. Which database relationships can you explain?

Trend is linked to Metric and Sentiment records through trend_id. A trend can have multiple recorded metrics. A foreign key associates the child record with its parent.

9. What happens when the API fails?

The application should display an error rather than fabricated results. A quota or network failure is different from a valid search returning no videos.

10. What does real-time mean here?

The application requests current available API data when a search runs. It is not a continuously streaming feed, and upstream statistics may not update instantly.

11. Does a 7-day filter mean views gained during seven days?

No. The publication filter selects videos within a period; the returned view counts are accumulated counts. Measured growth requires stored comparisons.

12. Why might a historical window remain pending?

There may be too few saved observations, no suitable baseline for the interval, a changed video cohort, or a persistence issue. The next step is to inspect the saved observations and their timestamps.

13. How accurate is the system?

API fields, arithmetic, sentiment labels and projections require different validation. I would not claim a single accuracy percentage without a defined evaluation dataset and method.

14. How did you test it?

Backend tests and targeted frontend rendering checks cover calculations and important states such as missing history. Manual demonstration should also cover search, filters, charts and exports. These checks are not proof that every browser or external API condition is covered.

15. What security measures matter?

Keep service credentials on the server, validate user input, escape displayed content, and safely generate downloadable reports. Explain implemented controls without claiming the application is completely secure.

16. What are the main limitations?

Analysis covers a retrieved sample, depends on external API availability, needs comparable persisted history, and has limited sentiment reliability. Scheduled collection is not implemented.

17. What would you improve next?

Add scheduled collection with durable storage, track stable video cohorts, evaluate sentiment against labelled examples, and validate forecasts against later observations.

18. Is this a machine-learning project?

It is a data analysis system with an NLP sentiment component and heuristic indicators. The core implementation does not justify claiming a custom-trained prediction model.

9. Preparation for both project partners

Both partners should understand the complete request flow. Divide the presentation for clarity, not to avoid learning the other half.

  • Partner A: introduction, problem statement, scope, frontend and live search.
  • Partner B: backend, metrics, data models, historical limitations and exports.
  • Both: rehearse the engagement example, explain why history may be pending, and answer what the team actually implemented.

Describe individual contributions truthfully. If asked about an unfamiliar detail, explain what you know and identify the source file you would inspect rather than inventing an answer.

11. Final revision checklist

  • Give the introduction without reading.
  • Explain one complete request from browser to API and back.
  • Calculate 5% engagement and 20% growth from the examples.
  • Distinguish publication filters from measured historical changes.
  • Explain the baseline, snapshot identity and missing-history state.
  • Open a report and interpret its fields.
  • State three limitations and two future improvements.
  • Keep your laptop, network access and a clearly labelled backup report ready.
Practice question: “If the system shows millions of views but has only one saved observation, what can you conclude?”
You can describe current popularity and engagement. You cannot establish measured historical growth or acceleration from that single observation.
